# 2026-11-05: a stream of small items, local model against Haiku

The eval harness #224's first slice asks for: the same 40 small text items on a local model and on
a small hosted model, compared on accuracy, time per item and tokens. Every number here is
**measured**; the result files next to this note hold every answer.

## What was run

- Items: `fixtures/stream/tickets.jsonl`, 40 invented support messages, ten each of bug, billing,
  feature and question, a few deliberately close. Task: `fixtures/stream/task.md` (answer with
  one label word).
- Tool: `hrn feed` from harness branch `feed-command` at `cfefac4` (one read-only, tool-less,
  single-turn run per item, four at a time), scored by `scripts/stream-eval.sh`.
- **local-gemma4-26b**: `-b api --model gemma4-26b-a4b` against the inference repository's
  llama.cpp server on 127.0.0.1:8081 (`scripts/serve.sh`, Gemma 4 26B-A4B Q4_0, RX 7900 XT,
  `N_CPU_MOE=16 --cache-ram 0`, four slots).
- **haiku**: `-b claude --model haiku` on the Claude plan (Claude Code 2.1.284), all tools off.

## Results

| run | correct | median per item | p90 | items per second | output tokens |
|---|---:|---:|---:|---:|---:|
| local-gemma4-26b | 40 / 40 | 13.3 s | 20.0 s | 0.24 | 9,508 |
| haiku | 40 / 40 | 4.6 s | 6.7 s | 0.73 | 150 |

Per label, both were 10 of 10 on every label. Files: `results/stream/2026-11-05-local-gemma4-26b.jsonl`
and `results/stream/2026-11-05-haiku.jsonl` (with `.meta.json`).

## What it shows

- **Accuracy is equal** on this set: neither missed one, including the close calls.
- **The local model is three times slower** here, and the reason is visible in its output tokens:
  about 238 per one-word answer, because hrn's api loop always requests adaptive thinking, so the
  model reasons before every label. Haiku spent about 4 output tokens per item.
- Token counts are not comparable across the two: the Claude CLI reports only uncached input
  (2 tokens per item here), while the local server reports the whole prompt.
- So for this kind of stream the local model already scores the same at no plan cost; to move
  stream work to it the next slice is a way for `hrn feed` to turn thinking off (or lower the
  effort) on the api backend, then this eval again.

Not measured: larger or harder sets, other local models, and Haiku through `hrn batch` instead of
per-item runs.
